# 대제목 번호박스 일괄처리 구현 계획

## 목표

일반보고용 양식에서 대제목이 표 안에 들어가는 형태를, 사용자가 여러 문단을 선택한 뒤 `일괄처리`를 눌렀을 때 자동으로 생성한다.

현재 수동 삽입 기능은 `bufs/templates/대제목_번호박스.hwpx`를 채운 뒤 현재 커서 위치에 삽입한다. 일괄처리에서는 외부 파일 삽입 대신 현재 템플릿의 표 구조를 기준으로 HWPML 표 조각을 생성해 현재 문단 위치에 넣는다.

## 기준 템플릿 구조

기준 파일: `bufs/templates/대제목_번호박스.hwpx`

현재 구조:

- 1행 3열 표
- 1열: 번호 셀, 기본 텍스트 `1`
- 2열: 제목 셀, 기본 텍스트 `대제목`
- 3열: 마커 셀, 텍스트 `{{bufs_title}}`
- 표 전체 폭: `48196` HWPUNIT
- 셀 폭: `2487`, `45211`, `498`
- 행 높이: `2414`
- 표 아래 바깥 여백: `850`

3열 마커 셀은 화면상 거의 보이지 않지만, 현재 문서에서 이미 들어간 번호박스를 찾아 다음 번호를 계산하는 기준이다. 따라서 자동 생성 방식에서도 반드시 유지해야 한다.

## 구현 방향

1. `style-sets.json`의 대제목 스타일 항목에 `title_number_box` 역할을 부여한다.
2. 일괄처리에서 식별자 규칙이 대제목 항목과 매칭되면 일반 문단 스타일 적용 대신 번호박스 치환으로 분기한다.
3. 문단 텍스트에서 식별자를 제거하고 제목 문자열을 정규화한다.
4. 기존 `next_title_number_box_number()` 로직으로 다음 번호를 계산한다.
5. `대제목_번호박스.hwpx`의 `Contents/section0.xml`을 기준으로 번호/제목을 치환한 HWPML 조각을 생성한다.
6. 현재 문단 텍스트를 삭제하고, 같은 위치에 HWPML 표 조각을 `SetTextFile(..., "HWPML2X", "insertfile")`로 삽입한다.
7. 표 내부 셀 선택 일괄처리에서는 1차 구현에서 번호박스 치환을 하지 않고 일반 스타일/인라인 처리만 수행한다.

## 사용자 양식 변경 제약

사용자가 `대제목_번호박스.hwpx`를 직접 바꿀 수는 있지만, 자동 일괄처리와 번호 계산을 유지하려면 아래 계약을 지켜야 한다.

- 표는 1개만 둔다.
- 표는 1행 3열 구조를 유지한다.
- 1열은 번호 셀로 둔다.
- 2열은 실제 제목 셀로 둔다.
- 3열에는 반드시 `{{bufs_title}}` 텍스트를 유지한다.
- 3열은 아주 좁게 숨김 마커처럼 두는 것을 권장한다.
- 병합 셀, 여러 행, 그림, 도형, 떠 있는 개체, 복잡한 배경 이미지는 1차 자동 생성 대상이 아니다.
- 번호 텍스트와 제목 텍스트는 앱이 실행 시 덮어쓴다. 템플릿의 `1`, `대제목`은 샘플 값으로만 취급한다.
- 제목 셀에 적용된 문단/글자 스타일은 현재 문서에도 같은 이름으로 있어야 표시가 안정적이다.
- `{{bufs_title}}`를 제거하거나 이름을 바꾸면 기존 번호 스캔과 다음 번호 계산이 깨진다.

## 향후 확장

- `table-settings.json`에 폭, 셀 여백, 마커명 같은 제한된 프리셋 값을 노출한다.
- 템플릿에서 표 구조를 읽어 설정으로 저장하는 "프리셋 추출" 기능을 추가한다.
- 표 내부 문단 일괄처리에서도 번호박스 치환을 허용할지 별도 검증한다.

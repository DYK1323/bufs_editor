# 대제목 번호박스 일괄처리 구현 계획

## 목표

일반보고용 양식의 대제목처럼 "번호 + 제목 + 숨김 식별자"가 들어간 번호박스 표를 `일괄처리`에서 자동 생성한다.

## 기준 양식

기준 파일: `bufs/templates/대제목_번호박스.hwpx`

현재 기준 구조:

- 1행 3열 표
- 1열: 번호
- 2열: 제목
- 3열: 숨김 식별자 `{{bufs_title}}`
- 번호는 기존 문서 안의 `{{bufs_title}}` 표를 스캔해 최댓값 + 1로 계산

## 현재 구현 방식

1. `style-sets.json`의 일반보고용 대제목 항목에 `title_number_box` 역할을 둔다.
2. 기존 사용자 설정 파일에는 마이그레이션으로 같은 역할을 자동 보강한다.
3. 일괄처리 중 대제목 역할과 매칭되면 문단 앞 식별자를 제거하고 제목 문자열을 정규화한다.
4. 현재 문서 HWPML을 읽어 기존 번호박스 번호를 스캔한다.
5. 템플릿 HWPX 안의 번호와 제목 placeholder를 교체한 임시 파일을 만든다.
6. 현재 문단 텍스트를 삭제하고 같은 위치에 한글 카탈로그 액션 `InsertFile`로 그 임시 HWPX를 삽입한다.

중요:

- 자동 생성 경로에서는 HWPML 조각을 `SetTextFile`로 직접 삽입하지 않는다.
- 번호박스는 현재 "순수 TableCreate 재조립"보다 "템플릿 표를 InsertFile로 삽입"하는 쪽을 기본 경로로 사용한다.
- 이유는 셀 너비, 높이, 테두리, 여백, 번호 셀 폰트까지 템플릿과 정확히 맞추는 안정성이 더 높기 때문이다.

## 왜 이 방식을 쓰는가

한글은 표 전체를 먼저 만든 뒤 셀 속성을 나중에 덮는 방식에서 다음 문제가 있었다.

- 셀 너비가 무시되거나 균등 분배로 남는 경우가 있음
- 셀별 테두리가 전체 표 프리셋으로 뭉개지는 경우가 있음
- 번호 셀 글꼴/문단 스타일이 템플릿과 다르게 적용되는 경우가 있음

범정부오피스처럼 셀을 하나씩 만들며 속성을 즉시 적용하는 액션 흐름도 가능성은 있지만, 현재 구현에서는 템플릿 삽입이 더 안정적이다.

## 양식 변경 제약

- 표 구조는 1행 3열이어야 한다.
- 1열은 번호, 2열은 제목, 3열은 식별자 용도여야 한다.
- 3열에는 반드시 `{{bufs_title}}` 텍스트가 들어가야 한다.
- `{{bufs_title}}`를 제거하거나 이름을 바꾸면 기존 번호 스캔과 다음 번호 계산이 깨진다.
- 번호와 제목 placeholder는 각각 `1`, `대제목` 기준으로 치환된다.
- 병합 셀, 여러 행, 그림/도형/복잡한 배경 이미지는 현재 자동 생성 범위가 아니다.

## 향후 확장

- 사용자가 번호박스 템플릿을 교체할 수 있도록 템플릿 경로를 설정 UI와 연결한다.
- 필요하면 순수 액션 기반 셀 단위 생성 경로를 별도 실험 구현으로 추가한다.
- 여러 문단 선택 시 번호박스를 여러 개 생성하는 경우를 실제 한글 문서에서 회귀 검증한다.

# BUFS 한글 에디터 리팩터링 기능 명세서

작성일: 2026-07-22  
대상 앱: `bufs/hwp_style_mvp.py`  
문서 목적: 현재 구현된 BUFS 한글 문서 편집 자동화 앱의 기능을 기준으로 리팩터링 중 보존해야 할 동작, 분리해야 할 책임, 검증 기준을 정의한다.

## 1. 제품 개요

BUFS 한글 에디터는 Windows 환경에서 실행되는 Tkinter 기반 데스크톱 앱이다. 사용자가 한컴오피스 한글에서 문서를 열어 둔 상태에서 앱을 실행하면, 한글 COM 자동화(`HWPFrame.HwpObject`)를 통해 스타일 적용, 표 편집, 텍스트 정리, 표지 생성, 로고 삽입을 빠르게 수행한다.

핵심 사용자는 한글 문서의 보고서/공문/표 편집을 반복적으로 처리하는 실무자다. 앱은 문서 전체를 임의로 자동 변경하기보다, 사용자가 한글에서 선택한 문단, 텍스트, 표 셀, 커서 위치를 기준으로 보수적으로 동작해야 한다.

## 2. 실행 환경

### 2.1 필수 환경

- OS: Windows
- 한컴오피스 한글 설치 및 COM 객체 등록
- Python 3.11 권장
- Python 패키지: `pywin32`
- GUI: Python 표준 라이브러리 `tkinter`

### 2.2 실행 진입점

- 일반 실행: `bufs/run-mvp.ps1`
- 직접 실행: `bufs/.venv/Scripts/python.exe bufs/hwp_style_mvp.py`
- 스모크 테스트: `python bufs/hwp_style_mvp.py --smoke`
- 사전 검증: `bufs/verify-readiness.ps1`

### 2.3 주요 자산 파일

| 파일/폴더 | 용도 |
| --- | --- |
| `bufs/보고서 본문 서식.hwpx` | 스타일 목록과 스타일 ID를 읽는 기준 문서 |
| `bufs/style-order.json` | 스타일 목록 표시 순서 저장 |
| `bufs/table-settings.json` | 표 색상, 선, 제목셀, 여백, 단축키 설정 |
| `bufs/표지.hwpx` | 표지 생성 템플릿 |
| `bufs/logos/` | 삽입 가능한 BUFS 로고 이미지 |
| `bufs/test-output/` | 표지 생성물, 썸네일, 테스트 산출물 |

## 3. 리팩터링 목표

현재 앱은 단일 Python 파일에 GUI, 설정, HWPX 파일 처리, 한글 COM 제어, 클립보드 처리, 텍스트 변환 로직이 함께 들어 있다. 리팩터링은 기능 추가보다 책임 분리와 회귀 방지를 우선한다.

### 3.1 보존해야 할 사용자 가치

- 사용자는 한글 문서를 열고 앱 버튼을 눌러 현재 선택 영역에 작업을 적용할 수 있어야 한다.
- 스타일, 표, 정리, 표지/로고 기능은 현재와 같은 탭 기반 흐름으로 접근 가능해야 한다.
- 한글 연결 실패, 선택 영역 없음, COM 액션 실패는 사용자에게 명확히 안내되어야 한다.
- 위험한 변환은 선택 영역 기준으로만 실행되어야 한다.
- 대부분의 편집 작업은 한글의 일반 실행 취소로 되돌릴 수 있어야 한다.

### 3.2 권장 모듈 경계

| 모듈 후보 | 책임 |
| --- | --- |
| `app.py` | Tkinter 앱 조립, 탭 구성, 사용자 이벤트 연결 |
| `hwp_client.py` | 한글 COM 연결, HAction/HParameterSet 실행, 창 활성화 |
| `settings.py` | JSON 설정 로드/저장, 기본값 병합, 설정 정규화 |
| `styles.py` | 스타일 템플릿 읽기, 스타일 순서 관리, 스타일명 정규화 |
| `table_tools.py` | 표 테두리, 셀 색, 제목셀, 여백, 페이지 너비 맞춤 |
| `text_tools.py` | 숫자/날짜/줄바꿈/개요번호/규정명 변환 |
| `cover.py` | 표지 HWPX 생성, 자리표시자 치환, 대외비 제거 |
| `logos.py` | 로고 목록, 이미지 크기 판독, 썸네일, 삽입 |
| `clipboard.py` | 텍스트/HTML 클립보드 읽기 및 쓰기 |
| `models.py` | `PaletteColor`, `StyleRecord`, `HwpCandidate`, `CaptionParts` 데이터 클래스 |

리팩터링 중 새 의존성은 추가하지 않는다. HWP 자동화 동작은 공식 문서(`HancomDev/`)와 기존 검증 기록을 기준으로 유지한다.

## 4. 화면 구성 명세

앱은 `ttk.Notebook` 기반 탭 UI를 제공한다.

### 4.1 상태 탭

목적: 한글 연결과 현재 대상 문서를 확인하고 로그를 확인한다.

기능:

- `한글 연결 확인`: 실행 중인 한글 COM 객체에 연결하고 문서 상태를 로그로 표시한다.
- `대상 확인`: 현재 연결 대상 문서/창 정보를 표시한다.
- `테스트 문서 열기`: 스타일 테스트용 문서 복사본을 연다.
- `자산 다시 읽기`: 스타일, 설정, 로고 목록을 다시 로드한다.
- `실행취소`: 한글의 Undo 명령을 실행한다.
- 로그 영역: 앱 동작, COM 실패, 사용자 경고의 근거를 남긴다.

수용 기준:

- 한글이 설치되지 않았거나 COM 연결이 실패하면 앱이 종료되지 않고 오류 메시지를 보여준다.
- 문서가 없으면 편집 기능 실행 전 사용자에게 문서를 열도록 안내한다.
- 연결 후보가 여러 개여도 현재 활성/가시 창을 우선 대상으로 선택한다.

### 4.2 스타일/정리 탭

목적: 현재 문단/선택 영역에 스타일을 적용하고 선택 텍스트를 정리한다.

#### 4.2.1 스타일 목록

기능:

- `bufs/보고서 본문 서식.hwpx`의 `Contents/header.xml`에서 스타일 레코드를 읽는다.
- 스타일은 `StyleRecord(style_id, style_type, name)`로 관리한다.
- `style-order.json`에 저장된 순서가 있으면 UI 목록에 반영한다.
- 사용자는 스타일 목록에서 항목을 선택하고 `다시 적용`으로 현재 한글 문서에 적용한다.
- 사용자는 `위로`, `아래로`, `기본순서`로 표시 순서를 조정할 수 있다.

스타일 적용 정책:

- 스타일은 이름 기준으로 적용한다.
- 현재 문서에 동일 또는 정규화 기준으로 일치하는 스타일 이름이 있어야 한다.
- 스타일이 없을 때 임의 스타일로 대체하지 않는다.
- 스타일 적용 실패 시 로그에 스타일명과 실패 원인을 남긴다.

#### 4.2.2 텍스트 정리

기능:

- `줄바꿈/띄어쓰기 정리`: 선택 텍스트의 불필요한 수동 줄바꿈과 공백을 정리한다.
- `개요 기호 제거`: 수동으로 입력된 개요번호/글머리표 접두어를 제거한다.
- `｢규정명｣`: 선택한 한 줄 텍스트 앞뒤에 규정명 괄호를 삽입한다.
- `천원단위 쉼표 넣기`: 명확한 숫자에 천 단위 쉼표를 넣는다.
- `쉼표 빼기`: 숫자 내부의 천 단위 쉼표를 제거한다.
- 날짜 정규화:
  - `0000년 0월 0일`
  - `0000. 0. 0.`
  - `0000. 00. 00.`
- `요일 추가 (월)`: 날짜 뒤에 실제 요일을 추가한다.
- `요일 제거`: 날짜 뒤 요일 표기를 제거한다.
- `엑셀표 정리`: 선택 표/셀에 기본 배경, 글자색, 얇은 테두리, 표내용 스타일을 적용한다.

안전 규칙:

- 기본 동작은 한글에서 명시적으로 선택된 텍스트 또는 셀 범위에만 적용한다.
- 날짜, 전화번호, 문서번호, 학년도 표기는 숫자 쉼표 변환에서 보수적으로 제외한다.
- 여러 표 셀 선택은 셀별 순회 검증이 성공한 경우에만 일괄 변환한다.
- 표 셀 범위 전체 붙여넣기가 셀 구조를 흐트러뜨릴 가능성이 있으면 중단한다.
- 규정명 괄호 삽입은 한 줄 텍스트에만 허용한다.

수용 기준:

- 선택 영역이 없으면 경고 메시지를 보여주고 문서를 변경하지 않는다.
- 변환 결과가 원본과 같으면 붙여넣기를 실행하지 않는다.
- 변환 후 가능하면 선택 셀 또는 변환 텍스트를 다시 선택해 연속 작업을 돕는다.

### 4.3 표 편집 탭

목적: 한글 표에서 반복되는 셀 서식, 테두리, 제목셀, 캡션, 표 너비 작업을 버튼으로 처리한다.

#### 4.3.1 표 설정

기능:

- `table-settings.json`을 로드해 팔레트, 선 프리셋, 제목셀, 표 여백, 단축키를 구성한다.
- `표 설정` 창에서 색상 추가/삭제, 선/제목셀/여백/캡션 파서 설정을 변경하고 저장할 수 있다.
- 설정 저장 시 UTF-8 JSON으로 저장하며 한글 이름을 이스케이프하지 않는다.

기본 설정 항목:

- 팔레트: 노랑, 진회색, 회색, 연회색, 검정, 흰색, 셀배경
- 선 프리셋: `thin`, `thick`, `double`, `dotted`, `none`
- 제목셀: 배경색, 글자색, 문단 스타일, 글자 스타일, 테두리 조합
- 표 여백: 셀 안쪽 여백과 표 바깥 여백
- 단축키: 주요 기능별 단축키 문자열

#### 4.3.2 셀 색과 글자색

기능:

- 팔레트 칩으로 선택 셀 배경색을 적용한다.
- `선 없음` 또는 배경 없음 동작으로 셀 배경을 제거한다.
- 팔레트 칩으로 선택 텍스트/셀의 글자색을 적용한다.

수용 기준:

- 색상은 한글 COM의 `RGBColor` 값으로 변환해 적용한다.
- COM 속성 직접 설정과 HAction 실행 중 가능한 경로를 시도하고 결과를 로그로 남긴다.

#### 4.3.3 테두리 프리셋

기능:

- `얇은전체`
- `굵은외곽`
- `얇은상하`
- `굵은상하`
- `이중 아래`
- `좌우 없음`
- `점선 가로`
- `점선 세로`
- `얇은실선 가로`
- `얇은실선 세로`

수용 기준:

- 위, 아래, 왼쪽, 오른쪽, 내부 가로, 내부 세로를 구분해 적용한다.
- 선 종류와 굵기는 `table-settings.json` 프리셋을 기준으로 변환한다.
- `none` 프리셋은 선 없음으로 처리한다.
- 선택 상태가 맞지 않거나 COM 적용이 실패하면 문서 손상을 피하고 경고/로그를 남긴다.

#### 4.3.4 제목셀 자동화

기능:

- `제목셀 자동화` 버튼은 선택한 셀 범위에 제목셀 프리셋을 적용한다.
- 적용 항목:
  - 한글 표 속성의 구조적 제목셀 플래그
  - 제목셀 배경색
  - 제목셀 글자색
  - 제목셀 문단 스타일
  - 제목셀 글자 스타일
  - 제목셀 테두리 조합

수용 기준:

- 보이는 서식뿐 아니라 한글의 `Header` 속성까지 설정해야 한다.
- 부분 실패가 있을 경우 어떤 항목이 성공/실패했는지 로그에 남긴다.

#### 4.3.5 표 조작

기능:

- `셀 속성 복사/적용`: 선택 셀의 서식을 복사/적용한다.
- `표 바깥 여백 적용`: 설정된 표 바깥 여백을 적용한다.
- `쪽 너비 맞춤`: 현재 표 너비를 페이지 너비 기준으로 맞춘다.
- `markdown 표 → 한글 표`: 선택한 Markdown 표 텍스트를 HTML 표/TSV fallback 클립보드로 변환해 한글에 붙여넣는다.

수용 기준:

- Markdown 표는 헤더 구분선(`|---|`)을 포함한 표 형식만 변환한다.
- 붙여넣기는 가능하면 한글 원본 형식 유지 옵션을 사용한다.
- 페이지 너비 맞춤은 현재 표/문서 상태를 확인한 뒤 실패 시 경고한다.

#### 4.3.6 캡션 처리

기능:

- `표 제목 Cut`: 선택한 `[표 1-1] 제목` 또는 `[그림 1-1] 제목` 형태에서 제목 부분을 잘라 임시 보관한다.
- `캡션 조립`: 보관된 제목을 다음 선택 표의 캡션에 조립한다.
- `캡션원클릭`: 제목 잘라내기와 다음 표 캡션 적용을 한 번에 수행한다.
- 캡션 파서는 `table-settings.json`의 정규식과 템플릿을 사용한다.

수용 기준:

- 캡션 파서 설정 화면에서 샘플 인식 테스트가 가능해야 한다.
- 파싱 실패 시 잘라내기나 붙여넣기를 진행하지 않는다.
- 임시 보관된 캡션 제목은 로그 또는 상태로 추적 가능해야 한다.

### 4.4 표지/로고 탭

목적: 표지 템플릿과 BUFS 로고 자산을 현재 한글 문서에 삽입한다.

#### 4.4.1 표지 생성

기능:

- 사용자가 한글에서 제목, 날짜, 부서명 3줄을 선택한다.
- `선택 3줄로 표지 만들기`를 누르면 선택 텍스트를 파싱한다.
- `bufs/표지.hwpx`를 복사해 자리표시자를 치환한 새 HWPX 파일을 만든다.
- 치환 대상:
  - `{{문서제목}}`
  - `{{날짜}}`
  - `{{부서명}}`
- 대외비 표시 여부에 따라 `<대 외 비>` 영역을 유지하거나 제거한다.
- 생성된 표지를 현재 문서 커서 위치 또는 맨 앞 삽입 흐름에 사용한다.

수용 기준:

- 입력이 3줄 미만이면 경고하고 생성하지 않는다.
- HWPX 내부 XML은 UTF-8로 처리한다.
- 대외비 제거 시 단순 텍스트 삭제로 레이아웃이 깨지지 않도록 표 영역 단위 제거 방식을 유지한다.
- 생성물은 `bufs/test-output/cover-YYYYMMDD-HHMMSS.hwpx`에 저장한다.

#### 4.4.2 로고 삽입

기능:

- `bufs/logos/` 하위의 PNG, JPG, JPEG, BMP 이미지를 재귀적으로 읽는다.
- 이미지 파일의 픽셀 크기를 자체 파서로 읽는다.
- 가능한 경우 Windows WIA COM으로 썸네일 PNG를 생성한다.
- 사용자가 로고 버튼을 누르면 현재 한글 문서 커서 위치에 이미지를 삽입한다.

수용 기준:

- 로고 폴더가 없거나 이미지가 없으면 앱이 실패하지 않고 빈 목록으로 표시한다.
- 삽입 시 이미지 비율을 유지한다.
- 한글 삽입 실패 시 사용자에게 실패를 알리고 로그를 남긴다.

## 5. 공통 동작 명세

### 5.1 한글 연결

기능:

- `connect_hwp`는 `HWPFrame.HwpObject`에 연결한다.
- 한글 보안 모듈 등록을 시도한다.
- 실행 중인 한글 문서 후보를 수집하고 가시성, 경로, 문서 수, 창 정보를 기준으로 우선순위를 정한다.
- 각 기능 실행 전 `ensure_hwp`로 연결 상태를 보장한다.

수용 기준:

- `pywin32`가 없으면 명확한 오류 메시지를 제공한다.
- COM 연결 실패 세부 정보는 `LAST_HWP_CONNECTION_LOG` 또는 앱 로그에 남긴다.
- 한글 창 활성화가 필요한 붙여넣기/삽입 작업은 실행 후 한글 창을 활성화한다.

### 5.2 클립보드

기능:

- 선택 텍스트는 한글 `Copy` 명령 후 Windows 클립보드에서 읽는다.
- 텍스트 변환 결과는 유니코드 텍스트로 클립보드에 쓴다.
- Markdown 표 변환은 HTML Clipboard Format과 fallback TSV를 함께 제공한다.

수용 기준:

- 클립보드 열기 실패나 붙여넣기 실패는 문서 변경 성공으로 간주하지 않는다.
- 표 셀 변환에서는 셀 경계가 흐트러질 위험이 있으면 전체 붙여넣기를 중단한다.

### 5.3 로그와 사용자 메시지

기능:

- 모든 주요 버튼 액션은 성공/실패/변경 없음 상태를 로그에 남긴다.
- 사용자 조치가 필요한 경우 `messagebox.showwarning` 또는 `showerror`를 사용한다.
- 디버그성 COM 속성 실패는 앱 중단 대신 로그로 추적한다.

수용 기준:

- 예외가 발생해도 앱 전체가 종료되지 않아야 한다.
- 로그는 사용자가 문제 상황을 재현할 수 있을 만큼 버튼명, 대상 스타일/색상/프리셋, 실패 타입을 포함해야 한다.

## 6. 비기능 요구사항

### 6.1 안정성

- 원본 템플릿 파일을 직접 덮어쓰지 않는다.
- 생성물은 `test-output/`에 저장한다.
- 선택 영역이 없거나 대상이 불명확한 상태에서는 변경을 중단한다.
- 한글 COM은 버전/선택 상태에 민감하므로 가능한 대체 액션 경로를 두되, 성공 여부를 반드시 확인한다.

### 6.2 성능

- 앱 시작 시 HWPX/JSON/로고 목록 읽기는 사용자 체감상 즉시 완료되어야 한다.
- 로고 썸네일은 캐시 키를 사용해 반복 생성하지 않는다.
- 대용량 문서 전체 스캔이나 전체 문서 변환은 기본 기능으로 제공하지 않는다.

### 6.3 호환성

- 기본 문자 인코딩은 UTF-8로 유지한다.
- JSON 저장 시 `ensure_ascii=False`를 사용해 한글을 그대로 보존한다.
- 한글 버전 차이에 따른 COM 실패 가능성을 전제로, 액션명/파라미터셋 변경은 공식 문서와 실제 검증 후 반영한다.

### 6.4 유지보수성

- 텍스트 변환 함수는 한글 COM 없이 단위 테스트 가능해야 한다.
- HWPX 템플릿 조작 함수는 파일 복사본을 대상으로 테스트 가능해야 한다.
- GUI 이벤트 핸들러는 가능한 한 얇게 유지하고 도메인 로직을 별도 모듈로 이동한다.
- 설정 기본값과 사용자 저장값 병합 규칙은 한 곳에서 관리한다.

## 7. 리팩터링 수용 기준

리팩터링 완료는 코드 이동만으로 판단하지 않는다. 다음 기능이 기존과 동일하게 동작해야 한다.

### 7.1 필수 회귀 테스트

- `read_style_records`가 `보고서 본문 서식.hwpx`에서 스타일 목록을 읽는다.
- `style-order.json` 저장 순서가 스타일 목록에 반영된다.
- `table-settings.json`이 기본값과 병합되고 저장 시 UTF-8 한글이 유지된다.
- 숫자 쉼표 추가/제거가 날짜, 전화번호, 연도 표기를 보수적으로 피한다.
- 날짜 정규화와 요일 추가/제거가 유효한 날짜에만 적용된다.
- 수동 줄바꿈 정리와 개요 기호 제거가 순수 함수로 테스트 가능하다.
- Markdown 표 파서가 정상 표를 변환하고 비표 형식은 거부한다.
- 표지 생성 함수가 자리표시자를 치환하고 대외비 제거 옵션을 반영한다.
- 로고 이미지 크기 판독이 PNG/JPEG/BMP에 대해 동작한다.

### 7.2 수동 검증 시나리오

- 한글 문서를 열고 `한글 연결 확인`이 성공한다.
- 스타일 목록에서 스타일을 선택해 현재 문단에 적용한다.
- 표 셀 선택 후 셀 배경색과 글자색을 각각 적용한다.
- 표 셀 선택 후 `얇은전체`, `굵은상하`, `이중 아래`, `좌우 없음`을 적용한다.
- 표 첫 행 선택 후 `제목셀 자동화`를 적용하고 한글 표 속성의 제목셀 상태를 확인한다.
- Markdown 표 텍스트를 선택해 한글 표로 붙여넣는다.
- 선택 텍스트에 숫자 쉼표, 날짜 정규화, 요일 추가/제거를 실행한다.
- 3줄 텍스트를 선택해 표지를 생성하고 현재 문서에 삽입한다.
- 로고 버튼을 눌러 현재 커서 위치에 로고를 삽입한다.
- 각 편집 후 한글 `Ctrl+Z` 또는 앱 `실행취소`로 되돌릴 수 있다.

## 8. 리팩터링 제외 범위

- 새 UI 프레임워크 도입
- WebView, Pillow, NumPy 등 무거운 신규 의존성 추가
- 전체 문서 자동 정리 기본 제공
- 스타일이 없는 경우 임의 유사 스타일 대체
- 원본 한글/HWPX 템플릿 직접 수정
- 공식 문서나 검증 없이 한글 COM 액션명 추측 변경
- PyInstaller 배포 패키징 구조 변경

## 10. 제안 작업 순서

1. 순수 함수 테스트 추가: 텍스트 변환, 설정 병합, 스타일 목록 읽기, 표지 생성.
2. 데이터 클래스와 설정/텍스트/스타일/표지/로고 유틸을 별도 모듈로 분리.
3. 한글 COM 래퍼를 `hwp_client.py`로 분리하고 GUI와 COM 세부 구현을 느슨하게 연결.
4. 표 편집 기능을 프리셋 적용 단위로 분리하고 로그 결과 모델을 통일.
5. `MvpApp`는 탭 구성과 사용자 이벤트 연결 중심으로 축소.
6. Windows 한글 환경에서 수동 회귀 테스트를 수행하고 `verification-results.md`에 결과 기록.
